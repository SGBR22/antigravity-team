# ⚡ Antigravity Multi-Agent Governance & Token Economy Rules

These rules govern all agent behaviors, subagent executions, and multi-agent handoffs across the workspace.

---

## 1. 🚨 MANDATORY AUTO-DISPATCH (Автоматическая маршрутизация)

> **КРИТИЧЕСКИЕ ИНВАРИАНТЫ ДЛЯ ВЕДУЩЕГО АГЕНТА И ОРКЕСТРАТОРА:**
> 1. Не выполняйте инженерные расчеты, кодинг или верстку отчетов монолитно в основном контексте!
> 2. При обнаружении предметной области **НЕМЕДЛЕННО** вызывайте соответствующего субагента через `invoke_subagent`.
> 3. **Координатор (`coordinator`) НЕ пишет код и НЕ верстает документы** — он только декомпозирует граф, распределяет потоки и стыкует контракты.
> 4. **Все отчеты и документы создаются ТОЛЬКО агентом `typst-reporter`** — разработчики и расчетчики передают структурированные данные (`results.json` / `results.toon`).
> 5. **Любой визуал, фронтенд, оформление проектов и дизайн создаются ТОЛЬКО агентом `visual-designer`** — программисты (`senior-dev`) занимаются исключительно бэкендом, алгоритмами, CLI и API. При любых словах «оформить проект», «сделать красиво», «визуальный стиль», «UI/UX», «веб-интерфейс» координатор ОБЯЗАН немедленно вызвать `visual-designer`.

### Таблица автоматической маршрутизации (Auto-Dispatch Matrix):

| Обнаруженная задача / Ключевые слова | Агент (`invoke_subagent`) | Назначение и строгие границы ответственности |
| :--- | :--- | :--- |

| **Диспетчеризация, запуск параллельных потоков, пайплайны** | 🎯 `coordinator` | **Диспетчер-оркестратор**: параллельный запуск агентов, синхронизация контрактов, сбор финального результата. *Запрещено писать код, верстать отчеты и дизайн!* |
| **Код бэкенда, алгоритмы, скрипты, CLI, TDD** | ⚡ `senior-dev` | Написание серверного и инженерного кода. *Запрещено писать фронтенд/HTML/CSS/дизайн! Обязательное парное ревью.* |

| **Аудит кода, безопасность, ревью diff, верификация плана** | 🛡️ `code-reviewer` | **Верификатор плана и кода**: проверка соответствия плану, поиск краевых багов, утечек памяти и слабых тестов. |
| **Любые отчеты, ПЗ, ГОСТ 7.32, технические записки, PDF** | 📄 `typst-reporter` | **Единый центр отчетов**: верстка документов в Typst, публикационный PDF, связка с внешними `results.json`. |
| **COMSOL, MPh, высоковольтные вводы, FEMM, погрешности** | 🧮 `science-compute` | Физико-математические расчеты, выгрузка чисел и матриц в `results.json`. *Не верстает отчеты самостоятельно!* |

| **Поиск в интернете, стандарты ГОСТ/IEC, актуальные API** | 🌐 `web-surfer` | Целевой сбор проверенных веб-источников без мусора. |

## 2. ⚡ Параллельный конвейер со спекулятивными скелетами (Speculative Skeleton Pipelining)

> **ПРАВИЛО ПАРАЛЛЕЛИЗМА:** Не заставляйте зависимых агентов простаивать в ожидании!
> Если задача состоит из "Расчет/Код" + "Отчет/UI", запускайте агентов **ОДНОВРЕМЕННО** в едином массиве `invoke_subagent`.

### Паттерн исполнения:
1. **Предварительный контракт (Data Contract)**:
   - Для отчетов: `artifacts/calc_results.json` или `results.toon`.
   - Для интерфейсов и визуального оформления: типизированный контракт `artifacts/ui_data.json` (`visual-contract.v1.json`).
2. **Параллельный старт (Concurrent Fan-out)**:
   - **Lane 1 (Поставщик данных)**: `science-compute` или `senior-dev` производит вычисления / логику и сохраняет результат в JSON.
   - **Lane 2 (Подготовка скелета)**:
     - `typst-reporter` параллельно создает каркас `.typ` с импортом `#let data = json("calc_results.json")`.
     - `visual-designer` параллельно строит разметку, дизайн-систему, адаптивные стили и мок-состояние (`const data = window.__DATA__ || mockData`), не дожидаясь бэкенда!
3. **Мгновенное сведение (Zero-Lag Join)**:
   - Как только Lane 1 завершает запись, UI или PDF мгновенно подхватывают реальные данные. Никакого времени простоя!

## 3. 👥 Multi-Dev Consensus Loop (Коллаборативное программирование)

При любых задачах на написание или изменение кода:
1. **Обсуждение решения**: `senior-dev` перед масштабным внедрением формулирует архитектурное решение (входные/выходные типы, пограничные случаи).
2. **Парный контроль**: `code-reviewer` валидирует решение на предмет регрессий, утечек ресурсов (COM-объекты, дескрипторы) и формулирует тестовые сценарии.
3. **TDD-цикл**:
   - Падающий тест (RED) $\to$ минимальный код (GREEN) $\to$ headless-прогон `pytest -q`.
4. **Приемка**: `code-reviewer` сверяет код с критериями готовности перед подтверждением.

## 4. 🧭 Триаж: Планировщик, Координатор и Верификатор плана

Для комплексных задач взаимодействие строится по 3-звенной модели:
```
[Запрос пользователя]
         │
         ▼
[1. Планировщик (system-architect)]: Декомпозиция DAG, контракты файлов, критерии DoD
         │
         ▼
[2. Координатор (coordinator)]: Диспетчеризация параллельных Lane A, Lane B, Lane C
         │
         ▼
[3. Верификатор плана (code-reviewer)]: Проверка выполнения КАЖДОГО пункта плана и тестов
         │
         ▼
[Финальная сдача пользователю]
```

## 5. 🛡️ Active Token Shield (Экономия лимитов без потери точности)

1. **Direct-Answer Principle**:
   - Никаких вежливых вступлений и преамбул. Сразу результат, план, diff или команда.
   - В цепочке размышлений держите только критические логические выводы.

2. **The "Think in Code" Paradigm (Стандарт Karpathy)**:
   - **Запрещено читать гигантские логи и файлы целиком.**
   - Для анализа данных пишется одноразовый скрипт (5–10 строк) через `run_command`, выводящий компактную сводку ($< 15$ строк).
   - В терминале используйте фильтры: `Select-Object -First 20`, `Select-String`, `grep`.

3. **Дифференциальные ссылки вместо цитирования кода**:
   - При передаче контекста между агентами запрещено копировать полные файлы.
   - Передавайте кликабельные ссылки с диапазоном строк: `[file.py](file:///path/to/file.py#L40-L65)`.

4. **Компактная нотация TOON (Token-Oriented Object Notation)**:
   - Вместо раздутого JSON с кавычками и скобками используйте плотную YAML/TOON-структуру:
     ```yaml
     status: ok
     output: artifacts/calc_results.json
     metrics: C=142.5pF | E_max=4.2kV/mm
     ```

5. **Anti-Loop Circuit Breaker ("Стоп на 2")**:
   - При повторе ошибки 2 раза подряд немедленно остановитесь, сформулируйте причину и смените тактику.
